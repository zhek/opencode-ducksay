# Proposal

## Why

Сейчас плагин почти все сбои проглатывает: если шутка не пришла, утка молча говорит `Quack-quack!`; если не записался снимок, показывается только тост; кривые значения опций тихо заменяются дефолтом. Пользователь не может понять, почему утка не заговорила, а разработчик — собрать диагностику из issue. Нужен локальный файловый лог, который объясняет каждое решение плагина деградировать, не меняя поведение утки.

## What Changes

- Плагин SHALL писать диагностический лог в `<корень_проекта>/.opencode/ducksay/logs/`.
- Формат — JSON Lines: одна строка — один JSON-объект, UTF-8, `\n`.
- Имя файла — `ducksay-YYYY-MM-DD-N.log`, где `N` начинается с `1`; дата и время локальные.
- В каждом файле поле `time` — локальное время с offset, например `2026-11-07T18:42:10.004+03:00`.
- Один файл — не больше `1_048_576` байт; при переполнении создаётся следующий `N`.
- В папке `logs/` — не больше `7` файлов. Перед созданием восьмого удаляется самый старый по имени: сначала дата `YYYY-MM-DD`, затем числовой `N`.
- Уровень логирования задаётся константой `LOG_LEVEL = "warn"` в исходниках; пользовательской опции нет.
- Логируются события `joke.*`, `screenshot.*`, `copy.failed`, `config.invalid`, `plugin.setup_failed`, `command.failed`, `event.failed`.
- `config.invalid` пишется один раз при загрузке плагина; `joke.model_unusable` имеет уровень `info` и в дефолтный лог не попадает.
- В лог SHALL NOT попадать текст шутки, сообщения пользователя, промпт, ответ модели, содержимое файлов, diff или вывод инструментов.
- Папка `.opencode/ducksay/` по-прежнему создаётся по требованию и приносит собственный `.gitignore` со строкой `*\n`; существующий файл не перезаписывается.
- Успешные операции и штатные состояния (`busy`, `muted`, пустое копирование, узкая панель, ожидаемая отмена) не логируются.
- **BREAKING**: нет.

## Capabilities

### New Capabilities

- `error-logging`: хранение, формат и уровни диагностического лога; каталог событий; правила приватности; создание папки и `.gitignore`.

### Modified Capabilities

Нет. Поведение утки, диалога и панели не меняется: лог только описывает уже существующие пути деградации.

## Impact

- Новый модуль `src/log.ts`: форматирование строки, выбор файла дня, ротация по размеру и по количеству файлов, запись.
- Новый общий модуль `src/ducksay-folder.ts`: создание `.opencode/ducksay/` и `.gitignore` со строкой `*\n`; его переиспользуют скриншоты и лог.
- `src/joke.ts`: генератор сообщает типизированную причину отказа через колбэк, не получая зависимость от файловой системы.
- `src/screenshot.ts`: использует общий помощник папки и сообщает об ошибке `.gitignore`.
- `src/options.ts`: диагностика неверных значений опций для `config.invalid`.
- `src/tui.tsx`: создаёт логгер в `setup`, логирует перехваченные ошибки команд, событий и записи снимка.
- Тесты: `test/log.test.ts`, дополнения в `test/screenshot.test.ts`, `test/joke.test.ts`, `test/options.test.ts`, `test/setup.test.ts`.
- Документация: `docs/behavior.md`, `docs/behavior.ru.md`, `CHANGELOG.md` (`## Unreleased` → `### Added`). `README.md`, `README.ru.md`, `docs/configuration.md` и `docs/configuration.ru.md` не меняются: пользовательской опции у логирования нет, а подробности живут в `docs/behavior`.
- Публикуемые точки входа, зависимости и демо-GIF не меняются.
