# Design

## Context

См. `proposal.md` — Why. Поведение описано в `specs/ducksay-sidebar/spec.md`; здесь — состояние кода и решения, которые к нему приводят.

- `src/tui.tsx`: режимы `rest` / `swim` / `dock`; таймер плавания с шагом `TICK_MS = 33`, ранний выход при `mode() === "rest"`, `frozen()` или `swimSpeed <= 0`. Внутри тика `moveTowardsEdge` двигает утку, `state.wavePhase` двигает воду, затем `paint()` собирает девять строк.
- `laneLimit(laneWidth, artWidth)` возвращает максимальную левую колонку арта. Для полосы 37 и арта 8 это 29; середина полосы 18.5 соответствует левой колонке 14.5, потому что центр арта — `column + 4`.
- `src/tui.tsx` уже хранит `HEAD_ROW = 5`, `BEAK_ROW = 6`, `BODY_ROW = 7`, `LOWER_WATER_ROW = 8`, а строки 0–4 — резерв облачка. `QUESTION_ROW = 4`. Голова коровы может занять строки 1–3, язык — строку 4; нулевая строка остаётся пустой.
- `frozen()` — мемо ожидающей формы. Пока она истинна, тик плавания не запускается, поэтому корова и вода замирают без отдельной логики; таймер маркера остаётся единственным работающим.
- `DuckState` — снимок сессии, переживающий пересоздание раздела. `state.column`, `state.direction`, `state.wavePhase` и остальные поля уже восстанавливаются при переключении вкладок.
- `src/duck-state.ts` хранит необязательную `CowCameo`. `src/lane.ts` даёт `msPerColumn`, который для `swimSpeed / 3` даёт `3000 / swimSpeed`.
- `test/section.test.tsx` подменяет `schedule` ручными часами и монтирует раздел с `states`; `tick(frames, ms)` по умолчанию даёт кадры по 100 мс. Генератор случайных чисел подменяется пропом `random`.
- `CHANGELOG.md` уже имеет `## Unreleased` → `### Added`. Пользовательские README и `docs/` намеренно не должны упоминать корову.

## Goals / Non-Goals

**Goals:**

- Добавить корову отдельным чистым модулем, не раздувая `tui.tsx` арифметикой кадров и триггера.
- Получить ровно один бросок на каждое левое пересечение середины и не запускать второй выход, пока корова активна.
- Держать корову на том же тике, что и плавание, без второго таймера и без фоновой работы у скрытой сессии.
- Сохранить корову в снимке сессии, заморозить её вместе с водой при форме и убрать при входе в покой.
- Оставить пользовательские README и `docs/` без изменений; добавить только строку в changelog.

**Non-Goals:**

- Новые опции, настройки вероятности, цвета или формы коровы.
- Звук, отдельное облачко, реакция уточки, изменение направления или пауза плавания.
- Зеркальная корова, смотрящая вправо: она всегда смотрит влево, как уточка на левом ходу.
- Сохранение коровы на диск или между перезапусками OpenCode.
- Изменение публичного API плагина, `package.json` или entrypoint'ов.

## Decisions

### 1. Чистый модуль `src/cow.ts`

`src/cow.ts` держит всё, что можно проверить без рендера:

- `COW_WIDTH = 5`, `COW_CYCLE_COLUMNS = 10`, `COW_HOLD_STEPS = 1`, `COW_CHANCE = 1 / 50`, `COW_TOP_ROW = 1`, `COW_TONGUE_ROW = 4`;
- `crossedMidline(from, to, limit)` — истина только при `limit > 0`, `from > limit / 2` и `to <= limit / 2`; вызывающий код проверяет левое направление отдельно;
- `cowEmergence(columns)` — `columns <= 5 ? columns : 10 - columns`, с нулём вне диапазона `0..10`;
- `cowFrame(emergence, tongue)` — строки арта; `tongue` — фаза, а не следствие одной только ширины, потому что на выходе и на возврате `e = 4..2` выглядят по-разному;

- `advanceCow(cow, elapsedMs, swimSpeed)` — чистое продвижение накопленного времени на один тик, включая задержку на полном выходе.

Альтернатива — держать формулы прямо в `tui.tsx` — отклонена: триггер, арт и тайминг нужно покрыть десятком тестов, а рендер-тест не должен быть единственным местом, где они проверяются.

### 2. Триггер считается после шага утки

В цикле тика запоминаются `from = state.column` и `heading = state.direction` до `moveTowardsEdge`; после шага проверяется:

```text
mode() === "swim" && heading === -1 && crossedMidline(from, state.column, reach)
```

Полуоткрытое условие `from > limit / 2 && to <= limit / 2` даёт ровно одно срабатывание на пересечение. Проверка после `moveTowardsEdge` видит фактическую колонку, в том числе если шаг перескочил середину на несколько колонок. `mode() === "swim"` отсекает док, покой и заморозку; `reach > 0` — полосу без места для плавания; отсутствие таймера при `swimSpeed <= 0` отсекает нулевую скорость.

Бросок выполняется всегда, когда условие выполнено, даже если корова уже активна:

```text
const hit = (props.random ?? Math.random)() < COW_CHANCE
if (hit && state.cow === undefined) state.cow = { columns: 0, accumulated: 0 }
```

Так сохраняется правило «один бросок на пересечение», а вторая корова не появляется. Альтернатива — не бросать при активной корове — экономит вызов, но нарушает правило и делает поведение зависимым от того, успела ли корова убраться.

### 3. Состояние коровы живёт в `DuckState`

В `src/duck-state.ts` добавляется:

```ts
export interface CowCameo {
  columns: number
  accumulated: number
  held?: number
}

export interface DuckState {
  // ...
  cow?: CowCameo
}
```

`columns = 0` — невидимая корова; `columns = 1..9` — видимые колонки; на `10` корова удаляется. `accumulated` хранит остаток миллисекунд, чтобы шаг 33 мс не терял время. `held` считает уже потраченные интервалы задержки на полном выходе: при `columns = 5` первый интервал только увеличивает `held` до `COW_HOLD_STEPS`, а следующий начинает возврат. Поля необязательные, поэтому старые снимки и тесты без коровы остаются валидными.

Альтернатива — отдельная `Map<sessionID, CowCameo>` — дублирует жизненный цикл `DuckStates` и требует синхронизации при переключении сессии. Поле в снимке уже переживает пересоздание раздела и не добавляет второго источника истины.

### 4. Корова едет на тике плавания

Перед движением утки в каждом тике вызывается:

```text
state.cow = advanceCow(state.cow, TICK_MS, swimSpeed)
```

`advanceCow` использует `msPerColumn(swimSpeed / 3)`: при `swimSpeed = 10` это 300 мс на колонку. Пять колонок выхода, одна единица задержки и пять колонок возврата дают 11 интервалов, то есть полный цикл — 3.3 с. Внутри — накопление и цикл `while`, поэтому при высокой скорости одна колонка не теряется; при `120` цикл занимает 275 мс и укладывается примерно в восемь-девять тиков.

Задержка сделана частью `advanceCow`, а не отдельным таймером или полем с дедлайном: на полном выходе первый интервал увеличивает `held`, не меняя `columns`, поэтому на экране остаётся тот же кадр `e = 5`. Следующий интервал уже увеличивает `columns`, и корова начинает возврат. Так задержка наследует заморозку, пересоздание раздела и смену сессии от того же состояния.

Новая корова создаётся уже после этого шага, поэтому на тике броска она ещё не двигается: первый видимый кадр появляется через `3 / swimSpeed` секунд, а не в кадре броска. Существующая корова продвигается до движения утки; если она дошла до `columns = 10`, она удаляется до отрисовки.

Второго таймера нет. Тик уже останавливается на `rest`, `frozen` и `swimSpeed <= 0`, а `renderer` без таймера не запускает корову. Скрытая сессия не имеет своего таймера, поэтому её корова не двигается в фоне.

### 5. Арт и координаты

Видимые колонки `e` считаются как `cowEmergence(columns)`. Левая граница коровы — `laneWidth - e`, то есть корова прижата к правому краю и «входит» в стену. При `e = 5`:

```text
row 1: ^__^      (заканчивается на колонку раньше правого края)
row 2: (oO)\
row 3: (__)\
row 4:  U        (left + 1)
```

Пока корова выходит (`columns = 1..4`), глаза — `oo`, языка нет. На полном выходе (`columns = 5`) появляется `U`; этот же кадр стоит всю задержку. На возврате (`columns = 6..8`, то есть `e = 4..2`) язык остаётся: при `e = 4` и `e = 3` видны `(oO)\` и `U`, при `e = 2` — `^_`, `(o`, `(_` и `U` в последней колонке. На `e = 2` стена скрывает `O`, поэтому виден только `o`. На `e = 1` остаются `^`, `(`, `(` и языка нет, потому что `left + 1` уже за краем. На `e = 0` коровы нет. Кадр задержки на полном выходе — тот же `e = 5`; `held` не меняет арт, а только откладывает возврат.

`paint()` передаёт `cowFrame(e, state.cow.columns >= COW_WIDTH)`: по одной ширине нельзя отличить `e = 4` на выходе от `e = 4` на возврате, а язык должен быть только во второй половине цикла.

Решение оставить язык на `e = 2` принято сознательно: это последний кадр, где язык ещё виден, и он даёт более живой выход, чем обрыв на `e = 3`. Одноглазый кадр — следствие обрезки стеной, а не отдельный спрайт; в спецификации он описан явно, чтобы тест не считал его ошибкой. Альтернатива — убрать язык уже на `e = 3` — отклонена: она сокращает комедийный кадр и расходится с требованием «последний кадр с языком — `e = 2`».

`cowFrame(e)` возвращает только непустые строки: строку 1–3 и, если `e >= 2`, строку 4. `paint()` кладёт их через существующий `overlay` по `laneWidth() - e`; `wrapMode="none"` обрезает правый край, а тесты проверяют уже видимый срез. Верхняя строка шириной 4 не доходит до правого края, нижние строки шириной 5 доходят.

### 6. Порядок отрисовки и очистка

Корова рисуется до утки, чтобы утка оставалась на переднем плане, если спрайт когда-нибудь дотянется до резерва. Строки не пересекаются: корова занимает 1–4, утка — 5–7, вода — 7–8. Облачко показывается только в покое, а корова в покое уже удалена, поэтому они не встречаются. Маркер вопроса рисуется последним, как и раньше; если он попадает на строку 4, он перекрывает язык, а не наоборот.

`park()` — общая точка входа в покой — дополнительно очищает `state.cow`. Ветка `swimSpeed <= 0`, которая ставит `rest` напрямую, очищает корову там же. `paint()` дополнительно не рисует корову при `mode() === "rest"`: это страховка для старого снимка или смены сессии, а не основной механизм.

Корова продолжает цикл в `dock`, потому что тик там ещё работает. На повороте у края `park()` вызывается до `setMode("rest")`, поэтому последний кадр дока уже без коровы.

### 7. Заморозка и продолжение

`frozen()` уже останавливает тик плавания. Корова не получает отдельных проверок: её фаза остаётся в `state.cow`, вода — в `state.wavePhase`, маркер продолжает свой таймер. После закрытия формы тик запускается снова, и `advanceCow` продолжает с накопленного остатка. Это даёт точное продолжение без отдельного «замороженного» поля.

### 8. Подменяемый генератор случайных чисел

В `Ducksay` добавляется необязательный проп `random?: () => number` с умолчанием `Math.random`. В тестах `test/section.test.tsx` получает одноимённую опцию и передаёт её в компонент. Это единственная тестовая щель; в продакшене поведение не меняется.

Альтернатива — мокать `Math.random` глобально — хрупка: тесты рендера идут параллельно с другими файлами и могут влиять друг на друга. Проп явный и не меняет публичный API пакета.

### 9. Документация

README и `docs/` не меняются: это пасхалка, и её ценность в неожиданности. `CHANGELOG.md` получает только `- An Easter egg.` в `## Unreleased` → `### Added`; версия и `package.json` не трогаются. Полное описание остаётся в OpenSpec-артефактах этого изменения.

### 10. Тесты

- `test/cow.test.ts`: `crossedMidline` — левое пересечение, движение вправо, ровно середина, `limit = 0`; `COW_CHANCE` — ровно `1/50`; `cowEmergence` — 0..10; `cowFrame` — полный кадр с языком, закрытый рот на выходе `e = 4..2`, язык на возврате `e = 4..2`, отсутствие языка на `e = 1`, пустой кадр `e = 0`; `advanceCow` — интервал `3000 / swimSpeed`, один интервал задержки на `e = 5`, полный цикл за 11 интервалов, удаление на 10-й колонке, высокое `swimSpeed`.
- `test/section.test.tsx`: добавить `random` в `MountOptions`; тесты с `random: () => 0` (всегда выход) и `() => 1` (никогда): левое пересечение запускает, правое нет, промах не запускает, вторая корова не появляется, корова видна в строках 1–4, на выходе язык не появляется до полного кадра, полный кадр задерживается на один интервал, утка продолжает движение, высота не меняется, форма замораживает и отпускает, покой очищает, пересоздание раздела и смена сессии сохраняют фазу, потраченная задержка не повторяется после пересоздания, нулевая скорость не запускает, лишнего таймера нет.

## Risks / Trade-offs

- **Шаг 33 мс квантует тайминг.** Первый кадр при `swimSpeed = 10` появляется около 330 мс, а не ровно 300. → Спецификация задаёт номинальные `3 / swimSpeed` и `33 / swimSpeed`; тесты проверяют чистый `advanceCow` на точных миллисекундах и рендер — на кадрах по 100 мс. Не подгонять `TICK_MS` под косметический тайминг.
- **Задержка добавляет один интервал.** Полный цикл становится длиннее на `3000 / swimSpeed` мс, а при высокой скорости — на один тик. → Это осознанная часть требования: полный кадр с языком должен читаться, а `held` хранится в снимке сессии и не требует отдельного таймера.
- **На `e = 2` виден только один глаз.** Это выглядит как подмигивание и может быть принято за ошибку арта. → Явный сценарий в спецификации и тест на `^_`, `(o`, `(_`; альтернатива с удалением языка на `e = 3` отклонена.
- **Корова и маркер делят строку 4.** Маркер может закрыть `U`. → Маркер рисуется последним и важнее пасхалки; корова в покое уже удалена. Тест на заморозку проверяет, что маркер остаётся видимым.
- **Активная корова может пересечься с новой сессией.** Снимок сессии — единственный источник истины; при переключении старая корова не получает тиков. → Поле в `DuckState`, отсутствие отдельного таймера и тест на смену сессии.
- **Случайность делает тесты недетерминированными.** → Проп `random`; в продакшене `Math.random`, в тестах константы.
- **Пользователь не узнает о пасхалке из документации.** → Это осознанное решение; changelog даёт единственную подсказку, а OpenSpec хранит полное описание для сопровождения.
