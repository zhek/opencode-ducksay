# Design

## Context

См. `proposal.md` — Why. Здесь только то, что определяет технический выбор.

Боковая панель сессии TUI OpenCode — это конкретный компонент `packages/tui/src/routes/session/sidebar.tsx` в кодовой базе OpenCode. Наблюдённые факты, на которые опирается дизайн:

- Ширина панели фиксирована: `SESSION_SIDEBAR_WIDTH = 42`, поля `paddingLeft/Right = 2`, внутри у контейнера разделов есть ещё `paddingRight = 1` под скроллбар. Полезная ширина текста — 37 колонок.
- Панель публикует два слота: `sidebar.content` (внутри вертикального `scrollbox`, разделы отделяются `gap = 1`) и `sidebar.footer` (закреплён внизу).
- У `sidebar.content` нет собственных «детей»: все разделы, включая встроенные `Context` и `MCP`, приезжают как claim'ы плагинов. Порядок отрисовки — `before`, `prepend`, дети, `append`, `after`.
- Слот — это обычный JSX. Понятия «раздел» у хоста нет: заголовок раздела рисует сам плагин. Доменный стиль задают встроенные разделы: `<text><b>Заголовок</b></text>` основным цветом темы плюс строки приглушённым цветом.
- Слот выглядит только на маршруте сессии и скрывается настройкой пользователя `session.sidebar: "auto" | "hide"`, а также закрывается по `Escape`.
- OpenCode перезагружает плагин при изменении файлов из графа импортов: он сканирует импорты через `Bun.Transpiler.scan()` и ставит вотчер на каждый найденный файл, включая не-JS/TS.

## Goals / Non-Goals

**Goals:**
- Раздел `Ducksay` появляется в панели сессии после встроенных разделов.
- Фактическая отрисовка проверяется автоматическим тестом, а не только глазами.
- Пакет публикуем: ровно одна точка входа, без серверной.

**Non-Goals:**
- Утка ничего не говорит, не реагирует на события и не анимируется. Название плагина отсылает к `cowsay`, но говорящая версия — отдельный change со своим форматом реплики.
- Плагин не меняет ширину панели, не добавляет свой слот и не трогает `sidebar.footer`.
- Нет настройки для выравнивания, цвета или текста: всё статично.
- Не покрываем экраны, где панель скрыта, — это поведение пользователя и OpenCode.

## Decisions

### Раннер тестов — Bun

Тест отрисовки должен видеть реальный кадр. OpenCode тестирует свои же сайдбары через `testRender` и `captureCharFrame()` из `@opentui/solid` — механизм, живущий на нативных модулях OpenTUI и рассчитанный на Bun. Под `npx tsx --test` (Node) проверка фактической отрисовки невозможна в принципе.

Альтернатива: оставить `tsx --test` и ограничиться юнит-тестами чистых функций. Отвергнута — тогда «утка нарисовалась в панели» остаётся непроверяемым, и единственной защитой от регрессии будет ручной взгляд.

### Точка входа — `src/tui.tsx` с экспортом `./tui`

Пакет CLI-only: серверной точки входа нет, плагин регистрируется исключительно в `cli.json`. `Host.resolve` относится к отсутствующей серверной точке спокойно — возвращает `undefined` и продолжает.

Альтернатива: добавить `src/index.ts` и экспорт `"."`. Отвергнута: серверной стороне делать нечего, лишняя точка входа только создаёт обязательство её поддерживать.

### Арт хранится как TypeScript-константа

`src/duck.ts` экспортирует массив строк. Файл остаётся в графе импортов, поэтому его правка перезагружает плагин — как и при любом `.ts`-файле.

Альтернативы:
- Импорт арта из отдельного текстового файла (`import art from "...txt" with { type: "text" }`) — в Bun это работает из коробки, потому что лоадер `text` включён по умолчанию для `.txt`, и файл тоже попадает в граф импортов. Но требует ambient-объявления для `tsc`, включения каталога с артом в публикуемый пакет и отдельного соглашения о том, где этот файл лежит в репозитории. Дороже при нулевом выигрыше.
- `readFileSync(new URL(...))` — файл оказывается вне графа импортов, OpenCode его не отслеживает, и правка арта не перезагружает плагин. Кроме того, падение чтения в `setup` уносит весь плагин. Отвергнута.

### Выравнивание — левое, без расчёта отступа

Арт внутренне выровнен: ширины строк 4, 8, 8 при ширине блока 8, и ведущие пробелы задают положение частей утки. Центрировать по строке нельзя — флексбокс центрирует каждую строку по её собственной ширине и сдвигает голову `__` на две колонки вправо от тела. Единственный корректный способ — считать общий отступ блока, а это тянет магическую константу `37`, выведенную из ширины панели OpenCode.

Альтернатива: центрирование через `alignItems="center"` с ручным паддингом. Отвергнута по двум причинам: визуально ломает арт и жёстко связывает плагин с внутренней константой чужого проекта. Левое выравнивание от ширины панели не зависит вообще, а нулевой отступ совпадает с оформлением встроенных разделов.

### Размещение — `append` в слоте `sidebar.content`

Раздел добавляется после встроенных `Context` и `MCP`: встроенные разделы регистрируются первыми, поэтому `append` ставит `Ducksay` последним. Информационные блоки остаются сверху, декоративный — под ними.

Альтернативы:
- `prepend` — раздел оказывался бы первым, но тогда декорация задаёт тон всему блоку панели, а данные о контексте и расходах уходят вниз. Не выбрано.
- `sidebar.footer` — раздел не прокручивается, но там уже живут карточка Getting started и путь с веткой, и добавить туда третий блок — значит сломать композицию. Отвергнута.

### Подключение в разработке — `bun link` и имя пакета

`Host.resolve` различает цели: по имени пакета работает экспортная карта (`opencode-ducksay/tui` → `src/tui.tsx`), а по пути на каталог ищется файл `tui.ts` в корне. Чтобы раскладка совпадала с публикуемой и не дублировалась, плагин подключается по имени.

Альтернатива: `cli.json` с `file://`-адресом плюс реэкспортирующий шим `tui.ts` в корне. Отвергнута: лишний файл в корне, который нужно исключать из `files`, ради единственной выгоды — отсутствия глобального состояния. Отключение локальной сборки достигается префиксом `-opencode-ducksay` в том же `cli.json`.

### Зависимости OpenTUI — одновременно peer и dev

В рантайме OpenCode отдаёт плагину свои экземпляры Solid и OpenTUI; вторая копия Solid сломала бы реактивность, поэтому в публикуемом пакете они живут в `peerDependencies`. Тестам нужны реальные модули, поэтому те же имена дублируются в `devDependencies`. Публикуемая разметка от этого не меняется.

### Проверка отрисовки

Тест рендерит компонент раздела через `testRender` при ширине 42 и высоты, достаточной для заголовка и трёх строк, затем проверяет `captureCharFrame()`: кадр содержит `Ducksay` и все три строки арта у левого края. Отдельный сценарий подставляет строку шире 37 символов и убеждается, что переноса нет.

## Risks / Trade-offs

- **[Панель не видна в узком терминале и на экране home, либо раздел ушёл за нижнюю границу прокрутки]** → утка не отображается. Поведение определяется настройкой `session.sidebar`, шириной терминала и объёмом встроенных разделов. Митигация: описать в README как ожидаемое ограничение, не пытаться обойти его плагином.
- **[Ширина или вёрстка панели изменятся в OpenCode]** → левое выравнивание не сломается, но тест, рендерящий при ширине 42, начнёт падать. Митигация: считать это осознанным canary — падение сигнализирует об изменении компоновки, после которого тест обновляется осознанно.
- **[Локальная копия `solid-js` попадёт в node_modules и будет использована в рантайме]** → возможна поломка реактивности в TUI. Митигация: пакет в `peerDependencies`, dev-установка только для тестов; проверка фактической загрузки через `opencode plugin list` и логи.
- **[Тонкости JSX в тесте: `bun test` не подхватывает pragma сам]** → тест может не скомпилироваться. Митигация: явный `@jsxImportSource @opentui/solid` в файле теста плюс `jsxImportSource` в `tsconfig.json`; проверяется первым же запуском `bun test`.

## Migration Plan

Пользователь устанавливает пакет и добавляет строку в `~/.config/opencode/cli.json`:

```json
{
  "plugins": ["opencode-ducksay"]
}
```

Откат — удалить строку или добавить `-opencode-ducksay`; правки в состоянии проекта не требует. Миграции данных нет.
