# Design

## Context

См. `proposal.md` — Why. Здесь только состояние кода и ограничения, определяющие подход.

- `src/tui.tsx`: `bubbleVisible = mode() === "rest" && hasSwum && jokeReady()`. Спрайт выбирается по этому же признаку, облачко рисуется в `paint()` из `jokeText()`.
- `jokeReady` стартует как `props.joke === undefined`: статический `bubbleText` готов сразу, сгенерированная шутка — только после ответа.
- Запрос шутки начинается на переходе `busy` true→false, то есть в начале `dock`, а не в `rest`. Поэтому ответ может прийти раньше остановки.
- `src/bubble.ts` уже переносит по словам, режет до пяти строк и ставит `…`. Геометрия: 1–4 строки — нижняя граница на строке головы, хвостик на строке клюва; 5 строк — нижняя граница на строке клюва, хвостика нет.
- Таймер есть только у `swim`/`dock` (`TICK_MS = 33`). В `rest` таймера нет; `paint()` вызывается эффектом на `jokeReady`/`jokeText`.
- Тесты монтируют раздел на `ManualClock`, считают живые таймеры через подменённый `schedule` и читают кадры `captureCharFrame()`.
- `props.bubbleText` — тестовый шов; плагин его не передаёт.

## Goals / Non-Goals

**Goals:**

- Две анимационные фазы в покое: ожидание (`Quack...`) и печать по словам.
- Неподвижная утка и постоянные десять строк раздела.
- Та же геометрия облачка и тот же перенос по словам.
- Чистые функции для кадров и состояния клюва, проверяемые без рендерера.
- Ни одного таймера в покое с уже напечатанной шуткой.

**Non-Goals:**

- Новые опции для темпа.
- Звук, цвет, настоящее полужирное начертание.
- Изменение запроса шутки, таймаута и фолбэка.
- Устранение скачка геометрии на пятой строке.
- Печать статического `bubbleText`: это тестовый шов, он показывается сразу.

## Decisions

### Две фазы на одном признаке покоя

`resting = mode() === "rest" && hasSwum`. Дальше:

- `waiting = resting && props.joke !== undefined && !jokeReady()` — показываем `Quack...`;
- `typing = resting && props.joke !== undefined && jokeReady() && shown < total` — печатаем слова;
- `done = resting && props.joke !== undefined && jokeReady() && shown >= total` — показываем готовую шутку.

Облачко видно в любом из трёх состояний, то есть при `resting` для утки, которая уже плавала. Это и есть изменение: раньше `jokeReady()` был обязателен, теперь ожидание тоже показывает облачко.

Альтернатива — держать отдельный признак «запрос в полёте»: отклонена. `!jokeReady()` уже означает «ответа ещё нет», а запрос не начинается без плавания, так что отдельное состояние дублировало бы существующее.

Альтернатива — начинать ожидание уже в `dock`: отклонена. Утка движется, облачко ехало бы вместе с ней, а пользователь просил показывать ожидание с момента остановки.

### Кадры ожидания — чистая последовательность

`src/thinking.ts` экспортирует `THINKING_BASE = "Quack"`, `THINKING_STEPS = [1, 2, 3, 3]`, `THINK_FRAME_MS = 300` и `thinkingText(dots)`. Компонент держит индекс в `THINKING_STEPS` и раз в 300 мс делает `(index + 1) % 4`.

Видимая последовательность: `Quack.` → `Quack..` → `Quack...` → `Quack...` → `Quack.`. Повтор тройки — это и есть «кадр с тремя точками держится дольше»: 600 мс вместо 300. Чистая функция принимает число точек, поэтому проверяется без таймера, а повтор шага живёт в данных, а не в условии внутри тика.

Альтернатива — отдельный таймер на 600 мс для последнего кадра: отклонена, пришлось бы пересоздавать интервал и синхронизировать его с остальными кадрами.

Альтернатива — начинать с `Quack` без точки: отклонена. Пользователь выбрал цикл из трёх кадров, где точка есть всегда; кадр без точки был только заготовкой рисунка.

### Печать по словам

`src/thinking.ts` экспортирует `WORD_FRAME_MS = 180`, `bubbleWords(text)`, `revealText(text, count)` и `beakOpen(count, total)`.

`bubbleWords` режет по пробельным символам так же, как `wrapBubbleText` в `bubble.ts`. `revealText` возвращает первые `count` слов, соединённые одним пробелом. Перенос каждый кадр пересчитывается по префиксу: жадный перенос по целым словам префиксно стабилен, поэтому слово не прыгает между строками.

Первое слово показывается сразу при ответе: `shown` выставляется в `1` в том же обработчике, где `jokeReady` становится `true`. Пустого кадра между `Quack...` и первым словом нет. Если ответ пришёл в `dock`, `shown = 1` выставляется тогда же, но облачко невидимо; при входе в `rest` сразу видно первое слово.

Альтернатива — начинать с `shown = 0` и показывать первое слово через 180 мс: отклонена, между ожиданием и шуткой мелькало бы пустое облачко.

Альтернатива — печатать по буквам: отклонена. Перенос в облачке — по словам, поэтому растущее слово прыгало бы на следующую строку в момент, когда перестаёт помещаться; кроме того, сто символов по буквам — это около трёх секунд против примерно двух по словам.

### Такт клюва

`beakOpen(count, total)` возвращает `true`, если `count >= total`, иначе `Math.floor((count - 1) / 2) % 2 === 0`. То есть первые два слова — открыт, следующие два — закрыт, и так далее; последнее слово всегда открыто.

При 180 мс на слово клюв меняет положение раз в 360 мс — около 2.8 переключения в секунду. Это вдвое реже, чем при переключении на каждом слове (7–8 в секунду), и читается как кряканье, а не мерцание.

Альтернатива — переключать на каждом слове: отклонена пользователем как мерцание.
Альтернатива — отдельный таймер клюва: отклонена, два таймера могли бы разъехаться с печатью, а такт «на слово» делает клюв частью той же последовательности.

### Пауза после знака препинания

`holdsAfter(word)` возвращает `true`, если слово кончается на `.`, `,`, `!`, `?`, `;`, `:` или `…`. Перед следующим словом тик пропускается: слово остаётся на экране 360 мс вместо 180. Клюв в это время держит текущее положение.

Альтернатива — менять интервал таймера: отклонена. `Schedule` задаёт фиксированный шаг; пропуск тика даёт ту же паузу без второго механизма.

### Таймеры живут только в своей фазе

Два отдельных `createEffect`:

- ожидание — зависит от `mode()`, `hasSwum`, `jokeReady()`, `props.joke`; на каждом тике двигает индекс кадров;
- печать — зависит от `mode()`, `hasSwum`, `jokeReady()`, `jokeText()`, `props.joke`; на каждом тике увеличивает `shown`.

Эффект печати читает `shown` через `untrack`, чтобы тик не пересоздавал таймер на каждом слове. Оба эффекта возвращают `onCleanup(stop)`, поэтому смена режима, ответ, конец печати и размонтирование снимают таймер тем же путём, что и плавание.

Таймер печати останавливает себя изнутри, когда `shown` дошёл до `total`: иначе интервал продолжал бы тикать вхолостую, а требование «в покое с готовой шуткой таймеров нет» нарушилось бы. `activeTimers()` в тестах падает до нуля ровно в этот момент.

Эффект печати запускается на `jokeReady` false→true и перезапускается на смене `jokeText`; `shown` при ответе уже равен `1`, поэтому перезапуск не теряет первое слово.

Альтернатива — один таймер с фазой внутри: отклонена. Фазы переключаются разными событиями (ответ, конец слов), и общий эффект пришлось бы будить по обоим признакам, рискуя лишним перезапуском.

### Сброс на новом ходу

В ветке нового хода (`working === true`) существующий эффект уже сбрасывает `jokeReady` и `jokeText`. Туда добавляются `setShown(0)` и `setDotsStep(0)`. Ответ выставляет `setShown(1)`.

Статический `bubbleText` не анимируется: при `props.joke === undefined` `bubbleText()` возвращает `jokeText()` целиком. Это сохраняет существующие тесты геометрии и оставляет шов детерминированным.

### Отрисовка

`paint()` берёт текст из `bubbleText()` вместо `jokeText()`. Спрайт выбирается по `beakOpen()`, а не по `bubbleVisible()`. `bubbleVisible()` сводится к `mode() === "rest" && hasSwum`.

Эффект перерисовки получает дополнительные зависимости `dotsStep()` и `shown()`, поэтому смена кадра и слова перерисовывает строки без отдельного вызова `paint()` из таймера.

### Геометрия не меняется

`bubbleRows` и `wrapBubbleText` не трогаются. Рост облачка с одной до пяти строк — существующее поведение; теперь он виден по мере печати. На переходе с четвёртой строки на пятую нижняя граница уходит со строки головы на строку клюва и хвостик исчезает. Это единственный скачок, он принят: утка не двигается, раздел не меняет высоту.

## Risks / Trade-offs

- **[Облачко теперь видно во время ожидания]** → это и есть цель изменения; прежнее требование «пока ответа нет, облачка нет» заменяется.
- **[Скачок на пятой строке]** → редкие длинные шутки дёргают нижнюю границу на одну строку. Принято; резервировать пять строк с самого начала означало бы пустое высокое облачко.
- **[Долгая шутка печатается долго]** → 20 слов при 180 мс — 3.6 с. Шутки обычно короче, а всё, что длиннее пяти строк, и так обрезается.
- **[Клюв всё ещё может казаться частым]** → 2.8 переключения в секунду. Если на живом TUI этого много, следующий шаг — переключать каждые три слова; это правка одной константы.
- **[Статический `bubbleText` не печатается]** → тестовый шов ведёт себя иначе, чем сгенерированная шутка. Это осознанно: шов существует для геометрии, а не для анимации.
- **[Новый таймер в покое]** → если его не снять, раздел будет тикать вечно. Снимается тремя путями: ответ (ожидание), конец слов (печать), смена режима и размонтирование (оба).

## Migration Plan

Пользователь обновляет пакет и перезапускает OpenCode. Новых опций и миграции данных нет. Откат — закрепить предыдущую версию или отключить плагин префиксом `-`.
