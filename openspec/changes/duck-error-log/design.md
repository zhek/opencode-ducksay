# Design

## Context

Сейчас плагин уже умеет создавать `<корень_проекта>/.opencode/ducksay/screenshots/` и кладёт рядом `.opencode/ducksay/.gitignore` со строкой `*\n` флагом `wx`; существующий файл не перезаписывается, ошибка игнорируется. Лог должен повторить эту логику, а не заводить вторую папку с собственным `.gitignore`.

Основные пути деградации разбросаны по модулям:

- `src/joke.ts` — десять ранних `return undefined` и `catch`, включая `llmModel` без `/`, таймаут, пустой ответ и сбой удаления временной сессии;
- `src/tui.tsx` — `catch` вокруг буфера обмена и записи снимка;
- `src/screenshot.ts` — молчаливый сбой `.gitignore` и исключение при исчерпании имён;
- `src/options.ts` — неверные значения молча заменяются дефолтом или обрезаются.

Хост не даёт плагину файлового логгера, поэтому запись остаётся делом плагина. Пользовательской опции уровня нет: по решению для этого change уровень задаётся константой в исходниках.

## Goals / Non-Goals

**Goals:**

- Объяснить в файле каждое решение плагина деградировать: почему утка сказала `Quack-quack!`, почему не сохранился снимок, почему не сработало копирование, какая опция была проигнорирована.
- Ограничить диск: не больше семи файлов по `1_048_576` байт, то есть примерно 7 MiB на проект.
- Не менять поведение утки, тостов и снимков и не давать логгеру бросить исключение.
- Не писать в лог содержимое шутки, промпт, реплики пользователя и файлы проекта.
- Переиспользовать существующую логику `.gitignore`, а не дублировать её.

**Non-Goals:**

- Уровень `logLevel` как опция плагина, `cli.json` и `docs/configuration.md` не меняются.
- Ротация по дням, срок хранения в днях и отдельный файл на сессию.
- Запись успешных операций и штатных состояний (`busy`, `muted`, пустое копирование, узкая панель).
- Отправка логов куда-либо, кроме локального файла.
- Изменение публикуемых точек входа, зависимостей и демо-GIF.

## Decisions

### JSON Lines, а не текст

Одна строка — один JSON-объект. Это даёт стабильные поля, встроенное экранирование кавычек и переводов строк, разбор через `jq` и простые тесты. Текстовый формат пришлось бы парсить вручную и отдельно определять правила экранирования. Цена — чуть больший размер и менее уютное чтение глазами; для диагностики это приемлемо.

### Кольцо из семи файлов вместо хранения по дням

Имя файла — `ducksay-YYYY-MM-DD-N.log`, `N` начинается с `1`. Файл создаётся при переполнении предыдущего, а не при смене суток. В `logs/` всегда не больше семи файлов: перед созданием восьмого удаляется самый старый. Старость определяется по имени — сначала дата, затем числовой `N`, — а не по `mtime`: имя переживает копирование и `touch`, а `mtime` — нет.

Альтернативы:

- один файл с ротацией `ducksay.1.log` — проще, но глобальный предел в семь файлов и суффикс `-N` уже выбраны пользователем;
- файл на день без общего предела — не ограничивает диск при циклической ошибке;
- `mtime` — ломается при копировании и восстановлении файлов.

Номера сравниваются как числа: `-10` новее `-2`, хотя `ls` может показать иначе. Это осознанно: удаление не должно зависеть от лексикографической сортировки.

### Локальное время с offset

Имя файла использует локальную дату, поле `time` — локальное время в формате `YYYY-MM-DDTHH:mm:ss.SSS±HH:MM`. Так файл `ducksay-2026-11-07-1.log` не содержит строк, начинающихся с `2026-11-06T21:...Z`. Offset берётся у `Date` для момента события, поэтому переход на летнее время не делает время двусмысленным.

### Уровень — константа `LOG_LEVEL = "warn"`

По умолчанию пишутся `error` и `warn`; `info` существует для отладки и включается правкой константы. Опция `logLevel` намеренно не добавляется: пользователь отказался от неё, а значит `docs/configuration.md`, `.ru.md` и README не получают нового раздела. Переданный в опциях `logLevel` игнорируется.

### `config.invalid` один раз, `joke.model_unusable` — `info`

`llmModel` без `/` разрешается в `{ kind: "unusable" }` при загрузке. Это статическая ошибка конфигурации, поэтому `config.invalid` пишется один раз в `setup`. Отдельное событие `joke.model_unusable` остаётся на уровне `info`: при дефолтном `warn` оно не засоряет лог одной и той же причиной на каждом ходу, но разработчик может поднять уровень и увидеть каждый случай. При `warn` пользователь видит ровно одну строку и облачко `Quack-quack!`.

### Логгер — sink без обратных вызовов

`src/log.ts` принимает готовое событие и пишет строку. Он не знает о `context`, не вызывает хост-API, не бросает исключения и не логирует собственные сбои. Любая ошибка `mkdir`, `readdir`, `stat`, `appendFile`, `unlink` проглатывается.

`joke.ts` не получает зависимость от файловой системы: генератор сообщает типизированную причину через `onFailure`, а `setup` превращает её в событие. Так `joke.test.ts` остаётся без временных папок. Аналогично `screenshot.ts` сообщает о сбое `.gitignore` через `onWarning`, а фатальные ошибки по-прежнему бросает, и `setup` логирует их с фазой.

### Общий помощник папки

`src/ducksay-folder.ts` получает `ensureDucksayFolder(project)`:

- `mkdirSync(<project>/.opencode/ducksay, { recursive: true })`;
- `writeFileSync(.gitignore, "*\n", { flag: "wx" })`;
- существующий файл не трогается, ошибка игнорируется.

Скриншоты и лог используют один помощник. Это сохраняет уже существующее поведение из `ducksay-sidebar` и не создаёт второй `.gitignore` в `logs/`.

### Разрешение корня проекта

Лог использует то же разрешение, что и снимок: `session.location.directory`, затем `context.location.directory`, затем `data.location.default().directory`. Событие `config.invalid` происходит до первой сессии, поэтому для него берутся TUI-локация или локация по умолчанию. Если путь недоступен для записи, строка просто не пишется.

### Приватность и обрезка

В лог попадают только метаданные: имена событий, уровни, id сессии, пути, имена опций и их значения, коды ошибок, длительности и счётчики. Текст шутки, реплика пользователя, промпт, ответ модели, содержимое файлов, diff и вывод инструментов не пишутся. Исключение — текст ошибки хоста в `error.message` и `error.stack`, который плагин не формирует.

Перед сериализацией `error.message` обрезается до `1_000` символов, строковые значения `data` — до `500`, `stack` — до `10` строк, вся строка — до `16_384` байт. Если после обрезки строка всё ещё больше, событие не пишется: лучше потерять одну строку, чем получить невалидный JSON.

### Документация: только `docs/behavior`

Логи не меняют то, что README обещает читателю, и у них нет пользовательской опции. Поэтому `README.md`, `README.ru.md`, `docs/configuration.md` и `docs/configuration.ru.md` не меняются. Описание поведения, пути, имён файлов и формата живёт в `docs/behavior.md` и `docs/behavior.ru.md`; пользовательская запись — в `CHANGELOG.md` (`## Unreleased` → `### Added`). Это осознанное исключение из общего правила обязательной задачи документации, зафиксированное в `tasks.md`.

## Risks / Trade-offs

- **Логи всегда включены, у пользователя нет выключателя.** → Папка создаётся только при первом `warn`/`error`; диск ограничен семью файлами; при необходимости опцию можно добавить отдельным change.
- **Ротация удаляет самый старый файл, поэтому всплеск ошибок может вытеснить старые дни.** → Предел в 7 MiB — цена ограниченного диска; номер `N` и дата в имени сохраняют порядок.
- **Несколько окон TUI пишут в один проект.** → Только append и удаление, без переименований; в редком случае счётчик файлов кратковременно разойдётся, следующая ротация выровняет.
- **Текст ошибки хоста может содержать пользовательские данные.** → Плагин не добавляет туда содержимое сам; исключение явно описано в спеке.
- **`plugin.setup_failed` может потеряться, если `setup` упал до создания логгера.** → Логгер создаётся в начале `setup`; более ранние ошибки загрузки остаются в логе хоста.
- **`info`-события не видны в обычной сборке.** → Это отладочный уровень; изменение константы и перезапуск TUI — осознанный шаг разработчика.

## Migration Plan

Миграции нет: папка `logs/` появляется при первом событии, старые версии плагина её не создают. Версия пакета не меняется. Откат — удалить папку `logs/` и вернуть прежнюю версию плагина; `.opencode/ducksay/.gitignore` остаётся совместимым со скриншотами.
